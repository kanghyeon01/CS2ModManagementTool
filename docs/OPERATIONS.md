# 운영 안내

## 디스코드 명령

개인 서버 채널에 입력합니다. 명령은 `!`로 시작합니다. 관리자 본인 계정이 쓴 명령만 처리합니다.

| 명령 | 하는 일 |
| --- | --- |
| `!status` | 게임 빌드, 대기·진행 작업, 승인 대기, 이중화 상태, 가장 가까운 만료일 |
| `!jobs` | 최근 작업 10개 |
| `!approve <id>`, `!reject <id>` | 승인·거절 (봇 메시지 아래 ✅/❌ 반응을 누르는 것과 같습니다) |
| `!pause`, `!resume` | 자동 작업 멈춤·재개 (감시와 알림은 계속) |
| `!home on`, `!home off` | 집에 있음 모드: PC를 깨우지 않고 작업을 쌓아 둡니다 (휴가 때) |
| `!run update` | 지금 게임 업데이트 대응을 수동 실행 |
| `!run rehearsal` | 배포 없이 전 과정 시험 |
| `!run check` | Steam·포럼·GitHub를 지금 바로 확인 |
| `!cancel <작업id>` | 진행 중인 작업 취소 (PC가 다음 보고 때 멈춤) |
| `!clear` | 대기 중인 작업 모두 취소 (시험할 때 편합니다) |
| `!maintenance [시간]` | PC를 깨워 Windows로 켜 둠 (기본 2시간, 최대 12시간). `!pause`·집에 있음 모드여도 동작 |
| `!done` | 원격 점검 끝 → PC 종료 (켜지기 전이면 예약 취소) |
| `!update_tool` | NAS·서버의 도구를 GitHub `main` 최신으로 (검사 실패 시 자동 되돌림) |

복무 중 휴대폰은 보통 평일 일과 후(부대마다 다르지만 대략 18시~21·22시)와 주말에 쓸 수 있으므로,
승인이 필요한 일은 그 시간에 처리하시면 됩니다. 버그 수정은 기본값이 "승인 필요"이고 14일이 지나면
만료됩니다(변경은 GitHub 브랜치에 남습니다). 게임 업데이트 대응은 기본값이 "자동 배포"입니다.
`controller.toml`의 `[approval]`에서 `veto:12`(12시간 안에 거절하지 않으면 배포)로 바꿀 수 있습니다.

## 알림 읽는 법

- **게임 업데이트 감지** → 30분 뒤 PC 작업 시작.
- **게임 업데이트 대응 완료** + 모드별 줄:
  - "변경 없음, 정상 동작": 새 버전에서도 그대로 동작합니다.
  - "수정 후 배포 완료 1.3.0 → 1.3.1": Claude가 고치고 시험을 통과해 올렸습니다.
  - "정책 검사에 걸려 보류": 고친 내용에 허용되지 않는 것이 있어 배포하지 않았습니다. 검토용
    브랜치(`cs2mmt/review-...`)를 휴가 때 보세요. **이 경우 모드는 깨진 상태로 남습니다.**
  - "실패": 빌드나 스모크 테스트를 통과하지 못했습니다. 메시지의 사유를 보세요.
- **새 글 분류 결과**: 포럼·GitHub 새 글 요약, 분류, 답글 초안. 포럼 답글은 자동으로 달지 않으니
  필요하면 초안을 복사해 직접 올리세요.
- **⚠️ 지시문 주입 시도**: 누군가 AI를 조종하려는 글을 올렸습니다. 도구는 따르지 않았습니다.
- **이중화 경고**: 한 시스템이 응답하지 않습니다. 다른 시스템이 계속 일합니다.
- **인증 정보 만료 D-30** 등: 휴가 계획에 넣으세요.

## 원격 접속 (Jump Desktop)

1. `!maintenance` → 몇 분 뒤 "PC가 Windows로 켜졌습니다" 메시지.
2. Jump Desktop으로 접속해 필요한 일을 합니다. 예: Claude 토큰 갱신
   ```powershell
   claude setup-token
   notepad $env:LOCALAPPDATA\cs2mmt\secrets.toml     # claude_oauth_token 교체
   ```
3. `!done` → PC가 꺼집니다. 잊으셔도 정한 시간이 지나면 꺼집니다.

PC는 그동안 다른 작업을 하지 않고, `!done` 뒤에 쌓인 작업이 있으면 처리한 다음 꺼집니다.

## 휴가 때 할 일 (체크리스트)

1. `!home on` (PC를 직접 쓸 때 작업이 끼어들지 않게) — 복귀 전에 `!home off`.
2. Claude 토큰이 곧 만료되면 `claude setup-token`으로 새로 발급해 PC의 secrets.toml을 바꿉니다
   (휴가가 아니어도 `!maintenance` + Jump Desktop으로 할 수 있습니다).
3. 게임을 한 번 켜서 Paradox 계정 로그인 상태를 확인합니다(ModPublisher 자동 로그인용).
4. Steam 로그인 상태를 확인합니다.
5. Windows 업데이트를 이때 몰아서 합니다.
6. 보류된 변경(`cs2mmt/review-*` 브랜치)과 만료된 승인을 검토합니다.
7. `!run rehearsal`로 다시 확인하고 떠납니다.

## 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| "PC가 WoL에 응답하지 않습니다" | BIOS ErP 끄기, 랜카드 WoL 설정, 리눅스·Windows 양쪽에서 끈 뒤의 WoL 유지, NAS가 호스트 네트워크로 도는지 |
| PC가 켜졌는데 리눅스에 머무름 | `journalctl -u cs2mmt-boot-switch`, `efibootmgr`에 Windows Boot Manager가 있는지 |
| Windows에서 아무 일도 없음 | 자동 로그인, 예약 작업 "CS2MMT Agent", `work\agent.log` |
| "Steam did not install build ..." | Steam 로그인 풀림, 다운로드 제한, 디스크 공간 |
| "Paradox 계정 로그인이 풀려" | 게임을 켜 Paradox 계정으로 로그인 후 종료 |
| "Claude 세션 실패: ... rate limit" | 구독 사용량 한도. 도구가 6시간 뒤 다시 시도합니다 |
| "Claude 인증" ❌ (리허설) | 토큰 만료 → `claude setup-token` |
| 포럼을 하루째 읽지 못함 | 포럼의 봇 차단일 수 있습니다. GitHub 이슈로 제보받는 것을 권장합니다 |

각 작업의 전체 기록은 PC의 `work\<작업id>\` 폴더(`job.log`, Claude 세션 기록, diff, 스모크 테스트
결과)에 있습니다.
